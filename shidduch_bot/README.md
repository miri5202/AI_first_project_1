# 💍 בית נאמן – עוזר שידוכים (RAG)

בוט שעונה למשפחות על הנהלים של משרד השידוכים "בית נאמן" (משרד דמיוני לצורך התרגיל):
הרשמה, דמי שדכנות, שלבי ההצעה, פרטיות ושאלות נפוצות.
הבוט עונה **אך ורק** מתוך מסמכי המשרד. אם התשובה לא נמצאת בהם, הוא אומר שלא מצא מידע ומפנה למזכירות.

**בחירה מכוונת:** המאגר מכיל רק נהלים ולא פרטים של מועמדים. כך נשמרים הפרטיות והכבוד של המשפחות, והבוט לא יכול "לדלוף" מידע אישי.

## מבנה הפרויקט

```
shidduch_bot/
├── data/                      ← מסמכי המשרד (txt / md / pdf / docx)
│   ├── 01_אודות_המשרד.txt
│   ├── 02_הרשמה_למשרד.txt
│   ├── 03_דמי_שדכנות.txt
│   ├── 04_שלבי_התהליך.txt
│   ├── 05_פרטיות_וצניעות.txt
│   └── 06_שאלות_נפוצות.txt
├── config.py                  ← כל נקודות ההחלטה במקום אחד
├── rag_engine.py              ← טעינה, חלוקה, אינדקס ב-ChromaDB, חיפוש ותשובה
├── ingest.py                  ← בניית האינדקס מחדש
├── app.py                     ← הקליינט (Streamlit)
├── requirements.txt
└── .env.example
```

## הפעלה

```bash
python -m venv venv
venv\Scripts\activate          # ב-Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env         # ולהכניס את OPENAI_API_KEY
python ingest.py               # בניית האינדקס מהמסמכים
streamlit run app.py
```

## שאלות לדוגמה

- "כמה עולים דמי שדכנות בשידוך שני?"
- "מתי משלמים את דמי השדכנות?"
- "מה קורה אם שני שדכנים הציעו את אותה הצעה?"
- "איך מוחקים תיק?"
- "הקפאה?" ← שאלה קצרה, מדגימה את הרחבת השאלה
- "מה מזג האוויר מחר?" ← מדגימה שהבוט לא עונה מחוץ למסמכים

## איך זה עובד

1. **טעינה** – `SimpleDirectoryReader` של LlamaIndex קורא את כל המסמכים מ-`data/`.
2. **חלוקה** – `SentenceSplitter` מחלק לקטעים של 512 טוקנים עם חפיפה של 64.
3. **וקטורים** – כל קטע הופך לווקטור עם `text-embedding-3-small` ונשמר ב-ChromaDB.
4. **שאלה** – שאלה קצרה מדי (פחות מ-5 מילים) מורחבת קודם על ידי המודל.
5. **חיפוש** – מוחזרים 4 הקטעים הקרובים ביותר (cosine), וקטעים מתחת לסף דמיון 0.30 נזרקים.
6. **תשובה** – `gpt-4o-mini` עונה רק מתוך הקטעים, ומציין מאיזה מסמך נלקח המידע.

## נקודות ההחלטה

| # | החלטה | הבחירה | נימוק |
|---|-------|--------|-------|
| 1 | Vector DB | ChromaDB (שמירה מקומית) | נלמד בכיתה, חינמי, לא צריך שרת |
| 2 | ספרייה | LlamaIndex | לפי הדרישה |
| 3 | אופן החלוקה | לפי כמות טוקנים (512), עם שמירה על גבולות משפטים | זול ופשוט; חלוקה לפי משמעות יקרה יותר כי דורשת קריאות embedding נוספות |
| 4 | חפיפה | כן, 64 טוקנים (~12%) | מונע מצב שכלל חשוב נחתך בין שני קטעים (למשל סכום ותנאי התשלום שלו) |
| 5 | ספק API | OpenAI | הכי זול מבין האפשרויות |
| 6 | TOP K | 4 | מספיק הקשר לשאלות שמשלבות שני מסמכים, בלי הרבה "רעש" |
| 7 | מודלים | וקטורים: `text-embedding-3-small`, תשובה: `gpt-4o-mini` | זולים מאוד, תומכים בעברית, איכות מספיקה |
| 8 | הרחבת שאלה | כן, רק לשאלות של פחות מ-5 מילים | שאלה כמו "הקפאה?" מחזירה וקטור חלש; לא מרחיבים כל שאלה כדי לחסוך קריאה |
| 9 | צורת חיפוש | Cosine similarity + סף מינימלי 0.30 | המדד המקובל לווקטורי טקסט; הסף מונע תשובות מקטעים לא קשורים |

את TOP K ואת הרחבת השאלה אפשר לשנות גם מהסרגל הצדדי באפליקציה.

## 3 בעיות שנתקלתי בהן ואיך פתרתי

### בעיה 1: כפילויות במאגר הווקטורים
**הבעיה:** בכל הפעלה מחדש של האפליקציה המסמכים נטענו שוב ל-ChromaDB. אותו קטע הופיע כמה פעמים בתוצאות החיפוש, וגם שילמתי שוב על יצירת הווקטורים.
**הפתרון:** לפני הטעינה בודקים `collection.count()`. אם כבר יש וקטורים, טוענים את האינדקס הקיים עם `VectorStoreIndex.from_vector_store`. בנייה מחדש מתבצעת רק במפורש (`python ingest.py` או כפתור "בנה אינדקס מחדש"), ואז ה-collection נמחק קודם.

### בעיה 2: שאלות קצרות מדי לא מצאו את התשובה
**הבעיה:** שאלה כמו "הקפאה?" או "כמה עולה" יצרה וקטור דל במשמעות, והחיפוש החזיר קטעים לא קשורים או ציון דמיון נמוך.
**הפתרון:** הוספתי שלב הרחבת שאלה. שאלה של פחות מ-5 מילים נשלחת קודם למודל, שמנסח אותה כשאלה מלאה בהקשר של משרד שידוכים (למשל: "איך מקפיאים את התיק במשרד השידוכים ולכמה זמן?"). רק אחרי זה נוצר הווקטור. השאלה המורחבת מוצגת בממשק כדי שאפשר יהיה לבדוק אותה.

### בעיה 3: הבוט ענה גם על שאלות שאין להן תשובה במסמכים
**הבעיה:** על שאלה שלא קשורה למסמכים, החיפוש עדיין מחזיר את 4 הקטעים "הכי קרובים" גם אם הם רחוקים, והמודל ניסה לענות מהם או מהידע הכללי שלו.
**הפתרון:** שני צעדים:
1. סף דמיון מינימלי: קטעים עם ציון מתחת ל-0.30 נזרקים. אם לא נשאר אף קטע, מוחזרת תשובה קבועה בלי לפנות למודל בכלל.
2. הנחיית מערכת מחמירה שמחייבת לענות רק מהקטעים ולהחזיר משפט קבוע כשאין מידע, עם `temperature=0` לתשובות עקביות. בנוסף, ההנחיה מורה לבוט לא להכריע בשאלות הלכתיות ולהפנות לרב המשפחה.
